> MarketLens is a pre-sign policy firewall for AI Agent batches. The Agent proposes — Moss proves what each action would do — the user's policy decides what survives. Five proposed, two eligible, three blocked under Default policy. Zero signed. Zero broadcast. Not deployed on Monad. All evidence is real local Moss + Anvil, re-verified in the browser.

## 3-minute technical explanation

### Architecture

MarketLens is built around a **deterministic batch policy engine** that evaluates Agent proposals before any wallet signs.

**Agent proposals** are generated by a local deterministic planner (`packages/agent-planner`) from a synthetic market snapshot. Every proposal carries `source_type: "SYNTHETIC_AGENT_PROPOSAL"`.

**User policy** is defined as a `BatchPolicy` object with: per-action and batch-total payment limits, allowed capabilities and outcomes, conflict-blocking rules, evidence requirements, and fail-closed behavior. Three presets (Strict/Default/Permissive) are provided.

**Moss evidence** is generated through `@marketlens/moss-prediction-market` (a source-pinned Protocol adapter), `@themoss/simulator` (vendored Moss simulator), and local Anvil `debug_traceCall` on chain 143. Each proposal produces a structured `ActionReceipt` with: simulation result, decoded revert reason, trace provenance, state changes, and a canonical SHA-256 hash.

**The batch engine** (`packages/batch-policy/src/engine.ts`) calls `evaluateBatchWithEvidence()` which:
1. Verifies all Moss evidence via `verifyBatchArtifacts()` (99 integrity checks at release time)
2. Applies action-level policy rules (payment limits, outcome validation, simulation success)
3. Applies batch-level rules (total payment limit, same-market conflict detection)
4. Assigns structured reason codes: `PAYMENT_LIMIT_EXCEEDED`, `SIMULATION_REVERTED`, `BATCH_POLICY_CONFLICT`
5. Produces a `BatchReceipt` with eligible/blocked lists, per-proposal verdicts, and a canonical hash

**The API route** (`POST /api/evaluate-batch`) accepts policy parameters, loads pre-generated proposals and simulation results, runs the engine, and returns the Batch Receipt.

**The browser** independently re-verifies 60 Web Crypto conditions (`packages/batch-policy/src/browser-integrity.ts`) before unlocking the five-step workflow. A hash mismatch renders a fail-closed receipt-rejected state.

**An unsigned allowlist** is produced as the final artifact — a list of eligible actions with canonical hashes, ready for a hypothetical future signer to consume. No signer, wallet, or broadcast path exists in the current implementation.

### What is real
- Foundry Solidity contract + 44 tests
- Moss Protocol adapter (source-pinned, unmodified)
- Local Anvil `debug_traceCall` simulation
- Batch policy engine with deterministic verdicts
- Receipt hashing (recursive key-sorted canonical SHA-256)
- Browser Web Crypto integrity re-verification
- Next.js UI consuming pre-generated evidence artifacts

### What is pre-generated (not browser-triggered)
- Moss simulation outputs (generated during artifact build, verified at release time)
- Agent proposals (deterministic planner from snapshot fixture)
- Batch receipts (computed at artifact generation, re-verified at page load)

The browser demo **does not** trigger a new live Anvil simulation on demand. It re-verifies published canonical artifacts.

### Safety boundaries (on every screen)
`SYNTHETIC AGENT PROPOSAL` · `REAL LOCAL` · `UNSIGNED` · `NOT BROADCAST` · `NOT DEPLOYED ON MONAD`
